# 二、技术路线

请首先检查当前计算机的软件和硬件环境，包括：

- pip

请把检查结果记录到：

然后根据硬件自动选择合理方案。

优先考虑以下两个技术路线：

## 路线 A：FunASR

例如：

Paraformer 中文 ASR 模型。

优点：

- 中文效果较好
- 适合普通话
- 推理速度快
- 比较容易本地部署

## 路线 B：Whisper

例如：

openai/whisper-small
openai/whisper-base
或 HuggingFace Transformers 中的 WhisperForConditionalGeneration。

优点：

- 端到端模型结构清晰
- 文档丰富
- 容易进行实验
- 适合解释 Transformer Encoder-Decoder ASR 原理

请根据本机硬件、下载条件、训练成本和实现复杂度选择一个作为主模型。

如果没有非常明显的理由，我希望优先采用：

FunASR Paraformer 或 Whisper-small。

在确定之前，不要同时实现多个重量级模型。

最终 README 中必须清楚说明选择该模型的原因。

# 七、创新性改进

这是非常重要的一部分。

课程附加项要求：

“针对模型具有创新性改进，比基线性能明显提升。”

注意：

不要虚构结果。

不要为了创新性写一个实际上没有实现的模型。

请优先设计：

本科大作业能够真正完成，
实现成本低，
训练成本可接受，
能够做 ablation，
有概率降低 CER

的改进方案。

请在开始实现前分析 3 个候选方案，然后选择一个最实际的方法。

候选可以从以下方向考虑：

## 方案 1：数据增强

训练阶段加入：

- speed perturbation
- random gain
- background noise
- SpecAugment

比较：

Baseline

vs

Baseline + Augmentation

观察 CER。

这是优先考虑的方案。

---

## 方案 2：中文语言模型 / 解码后处理

对 ASR 输出加入轻量中文语言约束。

例如：

- beam search
- KenLM
- 中文词频
- 简单 contextual biasing

比较：

Greedy Decode

vs

Improved Decode。

但如果实现复杂度过高，不强求。

---

## 方案 3：领域词汇纠错

设计一个轻量中文 ASR post-processing 模块。

例如：

基于拼音相似度 + 中文词频进行同音字纠错。

pipeline：

ASR

↓

Raw Transcript

↓

Pinyin-aware Correction

↓

Final Transcript

例如处理：

“人工只能”

→

“人工智能”

这样的同音/近音错误。

可以构建一个简单领域词典：

assets/domain_lexicon.txt

但必须严格通过 test CER 验证效果。

---

最终请根据实际实验选择最有效、最容易复现的方法。

必须做：

Baseline CER

vs

Improved CER

并计算：

Absolute Improvement

Relative CER Reduction

例如：

CER_baseline = X

CER_improved = Y

Relative Reduction =
(X-Y)/X × 100%

如果实验没有提升：

不要伪造提升。

分析失败原因，并尝试合理调整。

# 八、评价指标

必须实现：

src/metrics.py

重点指标：

CER（Character Error Rate）

定义：

CER = (S + D + I) / N

其中：

S：Substitution
D：Deletion
I：Insertion
N：参考文本字符数

请自己实现一个 CER 或使用 jiwer，同时最好提供自己的 Levenshtein 实现方便课程讲解。

输出：

overall CER

以及：

Substitution
Deletion
Insertion

如方便，再计算 WER，但中文实验以 CER 为主。
